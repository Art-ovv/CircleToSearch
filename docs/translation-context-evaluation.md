# Контекст перевода связанных строк

## Что подтверждено по коду

`ScreenTranslator.textBlocksFromNodes` сохраняет границы входных TextNode.
`translateLanguageGroup` обрабатывает запросы одной языковой пары, но
`translateTextGroup` передаёт каждую строку в модель отдельно. Общий образец
экрана используется для определения языка, а не как контекст перевода.
PaddleOCR обычно возвращает визуальные строки, AssistStructure может вернуть
целый абзац. Следовательно, потери контекста зависят и от источника текста.

Например, английское предложение `The battery lasts up to` / `two days on a
single charge.` полезно переводить вместе. В соседних кнопках `Save` / `Cancel`
или сообщениях разных участников такое объединение ошибочно.

## Рекомендуемая реализация

Перед переводом формировать абзацы только из последовательных строк одной
колонки с совместимыми высотой, отступом и межстрочным расстоянием. Не соединять
разные языки, колонки, списки, подписи и элементы управления. Одной геометрии
недостаточно: текущие TextNode не содержат границ чат-пузырей и семантических
контейнеров. Поэтому сомнительные блоки должны оставаться отдельными.

Сохранять исходные идентификаторы и прямоугольники строк. Перевод предложения
меняет порядок и длину слов: нельзя распределять результат обратно по строкам
по числу символов или надеяться на сохранение переводчиком разделителей.
Для безопасного вывода нужен отдельный макет абзаца, учитывающий исходные
области строк. Закрашивание общего bounding box может стереть соседнюю иконку
или изображение между строками. При невозможности разместить весь перевод
следует сохранять оригинал, как делает текущий рендеринг для одного блока.

## Как проверить пользу до включения

Сравнить отдельные строки и целое предложение на одной версии локальных моделей
для RU→EN и EN→RU. Минимальный набор: перенос предложения, местоимение с
контекстом, отрицание на второй строке, идиома, техническое описание,
две колонки, список, соседние чат-пузыри и смешанные языки.
Оценивать смысл вручную (включая отрицание, числа и субъекта), отдельно измерять
время, число запросов и долю переводов, не помещающихся в исходную область.
Нужны регрессии на ошибочное объединение и сохранение посторонних пикселей.

## Решение этой итерации

Объединение строк не включено: это оценка, а не подтверждённое улучшение качества.
Без прогона моделей и проверки рендеринга нельзя утверждать, что выигрыш
контекста перевешивает ошибки объединения. Следующий шаг — эксперимент с
абзацами и отдельным макетом, сохраняющий текущий построчный режим как fallback.
