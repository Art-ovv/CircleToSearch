# Корпус OCR v1

Корпус находится в `app/src/androidTest/java/com/akslabs/circletosearch/ocr/`:
`OcrCorpus.kt` содержит эталоны и рендеринг, `OcrCorpusInstrumentedTest.kt`
запускает настоящий `PaddleOcrEngine` с моделями из APK.

12 синтетических экранов покрывают русский и английский текст, оба языка на
одном экране, подписи 18 px, тёмную тему, белый и чёрный текст на разных
подложках одного экрана, слабый контраст, наклон ±8°, неоднозначные символы
серийных номеров и изображение внутри чат-пузыря. Размер экрана 1080×1920 px,
обычный шрифт 36 px. Эталоны нарисованы Canvas; это проверка реального OCR,
но не репрезентативная оценка всех пользовательских скриншотов.

## Запуск на разрешённом тестовом устройстве

```sh
./gradlew connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.class=com.akslabs.circletosearch.ocr.OcrCorpusInstrumentedTest
```

Команда устанавливает и запускает тесты: использовать только при явно
разрешённом тестировании и подключённом нужном устройстве.
Прогон сохраняет `ocr-corpus-v1.json` в external files directory приложения
(либо internal files directory, если внешняя недоступна). Отчёт содержит
SHA-256 моделей и словаря, версию приложения, устройство, Android API,
эталон и результат каждого случая, CER, WER, точное совпадение и время.
Личные изображения и production-логи не используются.

CER — расстояние Левенштейна по Unicode code points, делённое на число
эталонных символов; WER — аналогично по словам. Нормализуются NFC и пробельные
разделители; регистр, пунктуация и различие `ё`/`е` сохраняются. Лишний OCR тоже
штрафуется. Порядок строк берётся из результата модели, так что ошибки порядка
отражаются в метриках. Сводные метрики взвешены числом символов/слов; случаи
с ошибкой выполнения перечисляются отдельно и делают прогон неуспешным.

Первый случай включает холодную загрузку; время остальных случаев — тёплое.
Это ориентир, не полноценный бенчмарк производительности. Для сравнения нужны
одинаковые устройство, Android, системный шрифт и условия нагрузки.

До измерения нет выдуманного порога качества: успешный тест означает завершение
измерений, а не приемлемую точность. После получения baseline можно добавить
`-Pandroid.testInstrumentationRunnerArguments.ocrMaxCer=<измеренный-порог>`.
При изменении эталонов увеличивать VERSION и имя отчёта. Реальные публичные
или разрешённые обезличенные скриншоты следует добавить отдельным набором с
лицензией, разметкой и происхождением; синтетические экраны их не заменяют.

В этой итерации запуск на устройстве не выполнялся; численных результатов нет.
